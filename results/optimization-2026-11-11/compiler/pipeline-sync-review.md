# Explicit synchronization review

Scope: `_decode_pipeline._prefill_kernel`, grouped G4, BM16, D128,
128 threads, page16, split16, BN32 and BN64. CPU lowering and NVCC resource
inspection only; no GPU or sanitizer run was performed by this reviewer.

Reviewed candidate SHA256:
`88493204f649a46069e7b5f5b1ee07bfe156b1bf302d536d0c02ba9fd4abec5e`.

No producer/consumer or buffer-reuse race was identified by static inspection
of the source and generated CUDA. This is a static conclusion, not a substitute
for the planned compute-sanitizer check.

## Ordering proof

1. **Qs and initial KV.** Qs is synchronously produced before the loop. The
   first iteration executes each thread's `cp_async_wait<0>()`, followed by a
   full `__syncthreads()`. This publishes both Qs and the initial KV slot before
   any QK ldmatrix. With zero blocks, there is no shared-memory consumer.

2. **Current-slot readiness.** The wait completes all pending copies issued by
   that thread; the subsequent CTA barrier makes every participating thread's
   completed shared stores visible to all consumers. The synchronous initial
   tail path is also published by this same barrier.

3. **Next-slot overwrite.** Iteration n prefetches into `(n+1)%2`, which is the
   slot consumed in iteration n-1. All threads must finish iteration n-1's PV
   work before they can pass iteration n's top barrier. Thus no next prefetch
   can overwrite data still being read from the old slot. Current QK/PV read
   `n%2`, a disjoint region from the prefetch destination.

4. **P production and consumption.** The generated `stmatrix` writes of P are
   followed by an explicit full CTA barrier before PV ldmatrix. The next
   iteration's top barrier retires all previous PV readers before any thread
   can rewrite P. No additional end-of-loop barrier is needed for this reuse.

5. **Tail and unaligned copies.** These branches synchronously write only the
   next slot and zero both K and V for inactive positions. Their producer
   stores precede the next iteration's top barrier. There is no pending async
   group for that copy, so the unconditional wait is harmless. Invalid logical
   pages are not read: the page-table lookup remains inside the live-token
   predicate. All full/tail decisions and the loop trip count are uniform
   within a CTA because they depend on batch length, split, and tile indices.

6. **Reduction workspaces.** The two workspace regions remain disjoint from
   Qs, both ring buffers, and P. `AllReduce<...,128,32>` performs an entry named
   barrier before each workspace write and a second barrier before peer reads.
   Each recursive level and each following collective has the next entry
   barrier, which retires the preceding peer reads before reuse. The manual
   synchronization flag does not remove these inline helper barriers.

For BN32, generated byte offsets are Qs=0, Ks=4096, Vs=20480, P=36864,
sum-workspace=37888, and max-workspace=38400. These regions do not alias.
The manual CUDA's top wait/barrier are at lines 90-91; P stmatrix/barrier are
at lines 204-205.

## Barrier counts

The comparison lowers the same current candidate, with `manual_bounds=True`
for both cases; only the thread-storage-sync pass is toggled.

| Mode | Pre-loop `__syncthreads` | In-loop source sites | Dynamic explicit barriers/tile | Named helper barriers/tile | Total CTA barriers/tile |
|---|---:|---:|---:|---:|---:|
| Automatic ThreadSync | 1 | 5 | 7 | 16 | 23 |
| Manual synchronization | 0 | 2 | 2 | 16 | 18 |

The two automatic source sites before max and sum are each executed twice for
BM16, hence five source sites mean seven dynamic barriers. Each cross-warp
128-thread/stride32 AllReduce has two recursive shared-memory levels and two
named barriers per level. There are two row maxima and two row sums per tile,
so sixteen named barriers remain. The 4-thread warp-shuffle AllReduces add no
CTA barrier.

The change therefore removes one pre-loop barrier and five CTA barriers per
tile. It does **not** reduce the total synchronization count to two per tile.

## Focused sanitizer coverage

The useful timing transitions are lengths 0, 1, BN-1, BN, BN+1, 2*BN,
2*BN+1, and 3*BN+1, covering empty tiles, the initial tail, a prefetched tail,
and reuse of a ring slot after two iterations. Include split1 plus a split
whose chunk is not page-aligned, page64 with BN32 (synchronous path), and
ragged batches. These are diagnostic additions; frozen benchmark cases and
numerical tolerances should remain unchanged.
